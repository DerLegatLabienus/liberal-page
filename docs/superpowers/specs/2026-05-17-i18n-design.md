# i18n + Shareable Language Links — Design Spec

**Date:** 2026-05-17
**Backlog items:** 3 (Multi-Language Support), 3a (Shareable Language Links)

## Overview

The app already has `react-i18next` configured with complete `he.json` and `en.json` locale files. Language switches via a header toggle and persists to `localStorage`. What's missing: ~15 UI strings bypass translation, language isn't reflected in the URL, and the parliamentary tracker has no Hebrew-only guard.

## Section 1 — Language Init & URL Sync

**Init priority:** `?lang=` URL param → `localStorage` → `'he'` default.

`i18n.ts`: read `new URLSearchParams(location.search).get('lang')` before the localStorage fallback. If valid (`'he'` or `'en'`), use it and write it to localStorage.

`Header.tsx` `toggleLang`: after `i18n.changeLanguage(next)`, call `history.replaceState(null, '', '?lang=' + next)` so the URL stays in sync without adding a history entry. The URL is then shareable and bookmarkable.

## Section 2 — Tracker Gating (English Mode)

`App.tsx` derives `const isHebrew = i18n.language === 'he'` from `useTranslation()` — re-renders automatically on language change.

- `<ParliamentStrip>` only renders when `isHebrew` — no strip, no data fetch in English
- `<ParliamentDrawer>` is not rendered when not Hebrew
- `Header.tsx` receives `trackerEnabled: boolean` prop; tracker button gets `disabled={!trackerEnabled}` and `title="Available in Hebrew"`

## Section 3 — Hardcoded String Migration

~15 strings across 4 files that bypass `t()`:

| File | Keys to add |
|------|-------------|
| `AddTrackingInput.tsx` | `tracker.tab_bill`, `tracker.tab_committee`, `tracker.tab_mk`, `tracker.placeholder`, `tracker.add_button`, `tracker.add_label` |
| `MkCard.tsx` | `tracker.recent_activity`, `tracker.recent_votes`, `tracker.ai_vote_summary`, `tracker.view_source`, `tracker.remove` |
| `CommitteeCard.tsx` | `tracker.chair_prefix`, `tracker.last_session_prefix`, `tracker.ai_session_summary`, `tracker.view_source`, `tracker.remove` |
| `Footer.tsx` | `ui.rights_reserved` |

Vote color keys in `MkCard` (`בעד`, `נגד`, `נמנע`, `נעדר`) stay hardcoded — they're Knesset API data values, not UI strings.

## Section 4 — Future Backlog: Live Parliamentary Translation

Parliamentary content items (bill titles, MK names, committee names, activity descriptions) are stored as plain Hebrew strings from the Knesset API. Future work: each item carries a stable **identity** (its Knesset ID). A translation cache maps `{ id → { he: string, en: string } }`. On first English-mode view, a translation is requested (LLM or translation API) and cached. Components check the cache and fall back to the raw Hebrew string.

This is out of scope for this implementation.

## What Is Not Changing

- Vote color matching keys (`בעד`, `נגד`, etc.) — Knesset API data values, always Hebrew
- Bill status labels in `BillCard` — also Knesset API data values
- Parliamentary content (bill titles, MK names, activity text) — no English source exists
