# Public Shareable Letter Pages — Design

**Date:** 2026-06-20
**Status:** Approved (serving mechanism = Option D, Cloudflare R2) — proceeding to implementation plan.
**Origin:** product-manager ideation loop → "unlock virality / organic growth."

## Problem & goal

Everything in the app is behind Google sign-in, so nothing can be shared and the movement has
no organic-growth funnel. Goal: every **published** advocacy letter gets a **public, read-only
page** with a rich link preview (WhatsApp/X/Telegram) and a "sign in & send to your MK" call to
action — turning a shared link into reach and new members. Member data is never exposed.

## Why the serving mechanism is the crux

The frontend is a **static single-page app on GitHub Pages**: the server returns the same
tag-less `index.html` for every path and JavaScript fills content in the browser. Link-preview
crawlers (WhatsApp/X/Telegram) fetch raw HTML, **do not run JavaScript**, and time out in a few
seconds — so a shared SPA URL yields a blank preview. The fix is to serve the share URL from
something that returns per-letter Open Graph tags at fetch time, **without** the Render free-tier
cold start (30–60 s) in the crawler's path.

**Chosen: Option D — Cloudflare R2 (object storage).** The backend renders the share artifacts
**once at publish time** (it is awake — an admin is acting) and uploads them to an R2 bucket that
Cloudflare serves always-on from the edge. No cold start in the crawler path, instant freshness
(no build/CI lag), and no per-request edge compute to maintain (unlike a Worker). Considered and
rejected: A (Express on Render — cold start breaks previews unless paid/kept-warm), C (build-time
static — rebuild/CI coupling + lag), B (Worker — per-request compute we don't need; its only
edge over D, same-URL crawler/human branching, isn't worth the moving parts).

## Locked decisions

- **Shareable unit:** published letters only (`status='published'`). Drafts/unknown → no object.
- **Letters stand alone:** a letter is subject + body + recipients; it has **no required link to a
  bill, MK, or vote** (recipients are free-form). The share page must present the letter on its
  own terms and must not assume any bill/vote/MK context. (Campaigns — a future admin-only feature
  — will reuse this share pipeline for bill-optional advocacy bundles.)
- **Serving:** Cloudflare R2, objects written by the backend on publish, served via a Cloudflare
  custom domain.

## Architecture & data flow

```
Admin publishes/edits letter
        │
        ▼
 Express admin-letters route ──► share-publisher service
        │                          1. render share HTML  (standalone, OG tags)
        │                          2. render OG image PNG (templated card)
        │                          3. PUT both to R2  (key: letter/<id>.html, letter/<id>.png)
        │
Admin unpublishes / deletes ──► share-publisher.remove(id) → DELETE both R2 objects
        │
        ▼
Crawler / human ──► https://<share-domain>/letter/<id>  (Cloudflare edge serves the R2 object)
                       • crawler reads OG tags → preview
                       • human sees preview + CTA button → GitHub Pages app /letters/<id>?src=share
                                                            (sign-in → existing send flow)
```

Generation happens **synchronously after the DB write succeeds**, but failures are swallowed and
logged (a share-publish failure must never fail the admin's letter save — same "never throw"
contract as the email service). A published letter whose object is missing can be re-generated by
re-saving it (and a future backfill script can reconcile).

## Components (small, single-purpose units)

1. **`server/services/share-renderer.ts`** — pure rendering. `renderShareHtml(letter)` → standalone
   HTML string with OG tags + body preview + CTA; `renderShareImage(letter)` → PNG `Buffer`
   (templated card). No I/O, no R2 — unit-testable in isolation.
2. **`server/services/r2-client.ts`** — thin S3-compatible wrapper (`putObject`, `deleteObject`)
   over the AWS S3 SDK pointed at the R2 endpoint. **No-ops (returns false) when R2 env vars are
   unset**, so dev/test and an unconfigured prod never break (mirrors the email service's
   no-key no-op).
3. **`server/services/share-publisher.ts`** — orchestration: `publish(letterId)` reads the letter,
   guards `status==='published'` + the feature flag, renders via (1), uploads via (2);
   `remove(letterId)` deletes both objects. Never throws.
4. **Hook points in `server/routes/admin-letters.ts`** — after a successful create/update/pin
   (`POST`/`PUT`/`PATCH /:id/pin`): if the resulting letter is published → `share-publisher.publish`;
   if it became non-published or is deleted (`DELETE`) → `share-publisher.remove`. Fire-and-forget
   (`setImmediate`), logged.
5. **Feature flag `publicSharePages`** (seeded, default **off**) — gates all generation, so the
   capability ships dark and is switched on from the admin panel once R2 + the domain are live.

## Share page content (the standalone HTML)

Hebrew-first, RTL, minimal inline CSS (no SPA, no JS needed):
- Issue tag(s) + letter **title**.
- A readable preview of the **sanitized** body (already sanitized at store time).
- Recipient **display names** (not addresses, not a send mechanism).
- Primary CTA button: **"הצטרפו ושלחו לחבר הכנסת"** → `https://<app>/letters/<id>?src=share`.
- The existing privacy-notice line (sends are counted anonymously).
- Movement branding/logo.

## Open Graph / preview tags

`og:title` = letter title · `og:description` = first ~150 chars of `body_plain` · `og:image` =
`https://<share-domain>/letter/<id>.png` · `og:type=article` · `og:url` = canonical share URL ·
`twitter:card=summary_large_image` · `<html lang="he" dir="rtl">`.

## OG image (share card)

Templated card (movement logo + letter title + a CTA line on brand background), rendered with
**satori** (HTML/JSX → SVG) + **@resvg/resvg-js** (SVG → PNG), using the **Heebo** font already
bundled for the site (needs a `.ttf`/`.otf` variant for satori). Target 1200×630. Pure function in
the renderer; covered by a smoke test (produces a non-empty PNG of expected dimensions).

## URL & object-key structure

- Object keys: `letter/<id>.html` (Content-Type `text/html; charset=utf-8`) and
  `letter/<id>.png` (`image/png`).
- Public base: a Cloudflare custom domain bound to the bucket (e.g. `share.<domain>`). Until that
  domain exists, the `r2.dev` dev URL works for testing. The base URL is an env var.

## Configuration / secrets

Env vars (all optional; absence ⇒ no-op): `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`,
`R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PUBLIC_BASE_URL`. **Ops prerequisite (user action):** a
Cloudflare account, an R2 bucket, and a custom domain bound to it. This is the one non-code
dependency; the feature stays flag-off until it's provisioned.

## Privacy & security

- Only `status==='published'` letters ever produce an object; unpublish/delete removes it
  (no stale public pages).
- Body HTML is already sanitized server-side at store time (strict allowlist); the renderer
  inserts that already-sanitized HTML into the page — no new sanitization path is introduced.
- **No member or PII data** on the page or in analytics — only the admin-authored letter content
  and recipient display names (public officials).
- R2 write credentials live server-side only; the bucket is public-read, private-write.

## Analytics (lightweight, v1)

No tracking on the R2 page itself (it's static, off our backend). The CTA carries `?src=share`;
the app logs share-originated arrivals through the **existing** anonymous analytics pattern
(bucketed, no PII). Richer share metrics are out of scope for v1.

## Dev / test behavior

- With R2 env unset (dev/test/CI), `r2-client` no-ops and `share-publisher` short-circuits — the
  app behaves exactly as today. No test needs network or real R2.
- Tests: `share-renderer` (OG tags present, title/desc/CTA correct, published-only, PNG smoke);
  `share-publisher` with a mocked `r2-client` (publishes on published, removes on unpublish/delete,
  respects the flag, never throws on R2 error); admin-route hook fires publish/remove appropriately.

## Verification

`npm run lint` && `npx tsc --noEmit` && `npm test` && `npm run build`. Manual: set R2 env to a test
bucket, publish a letter, confirm `letter/<id>.html` + `.png` exist and the HTML carries the OG
tags; paste the URL into a link-preview validator (e.g. the platform debuggers) and confirm the card.

## Out of scope / future

- **Campaigns** (admin-only, bill-optional advocacy bundles) — will reuse this share pipeline.
- Public **bill** and **MK** share pages — same mechanism, different renderer; later.
- A Cloudflare **Worker** — only if we later want same-URL crawler-vs-human transparent redirects.
- Backfill/reconcile script for already-published letters when the feature is first switched on.
